## 2026-08-07 - Uninitialized SDK context and unhandled rejections in Zoho Catalyst
**Vulnerability:** Under Zoho Catalyst Node.js serverless functions, using the `app` instance outside the handler context where it is initialized causes ReferenceErrors or undefined property access runtime crashes. This could lead to partial denial of service (DoS). Furthermore, performing datastore/filestore actions without try-catch blocks or Promise catch handlers causes unhandled promise rejections, risking severe server instablity or crashing.
**Learning:** The Catalyst SDK context must be initialized on a per-request basis with `catalyst.initialize(req)` inside every request handler, rather than relying on global/function scope across multiple route handler declarations.
**Prevention:** Always scope `const app = catalyst.initialize(req)` inside every endpoint handler function. Wrap all database and filestore operations in robust try-catch blocks, returning generic error messages to avoid internal error/stack trace leakage.
