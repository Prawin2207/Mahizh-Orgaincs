## 2026-08-10 - [Secure and Stabilize Zoho Catalyst Node.js Functions]
**Vulnerability:** Global reference errors and unhandled promise rejections due to uninitialized global `app` references and missing/faulty route mappings. Specifically, calling `app.datastore()` or `app.filestore()` without initializing the Catalyst instance inside the request handler leads to crashes. Also, malformed requests or parameter injection could cause server crashes or data leakage.
**Learning:** In Zoho Catalyst serverless Node.js Express functions, the Catalyst application context must be initialized inside each individual request handler via `catalyst.initialize(req)` to prevent global scope/multitenancy reference errors. All backend endpoints must have comprehensive parameter/input validation and safe error handling that fails securely.
**Prevention:** Always initialize the SDK application context `catalyst.initialize(req)` inside every request handler. Use robust input validation for incoming bodies and params, wrap operations in `try-catch` blocks, and ensure endpoints return sanitized, secure error messages without leaking server stack traces.
