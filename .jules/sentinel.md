## 2026-08-09 - Localized Catalyst Initialization and Safe Input Validation
**Vulnerability:** Global reference of Zoho Catalyst's app context leading to ReferenceError crashes / denial of service, along with zero input validation/sanitization in product updates (mass assignment / parameter injection) and image loading (path-traversal or type crashes via unvalidated folder/file IDs).
**Learning:** Catalyst SDK context must be initialized inside each individual Express router handler scope with `catalyst.initialize(req)`. Failing to do so causes unhandled ReferenceErrors/scope errors. Furthermore, parameters passed directly to table updates and filestore downloads without sanitization allow arbitrary parameter manipulation and uncaught promise rejections.
**Prevention:** Always initialize `app` inside each handler function block. Validate inputs (such as validating query parameter types, sanitizing updated row fields, verifying numeric IDs for folders/files) and wrap all database/filestore operations in robust try-catch blocks to return sanitized, safe error messages to clients.
